# Review

Существенных блокирующих замечаний по исправлению зависания не выявлено.

Проверено:

- автоматический `eth_initialize()` в `common/main.c` отключён только для `CONFIG_CISCO_AP1800S`, поэтому U-Boot не должен сам переходить к EDMA/PHY сразу после старта;
- для Cisco default `bootcmd` пустой, что исключает автоматический запуск штатного `bootipq` при RAM-chainload;
- проверка размера встроенного RAM-only environment пропускается только для Cisco target;
- сборка raw `u-boot.bin` завершена успешно и файл повторно скопирован в TFTP и на удалённый хост.

Ограничение: фактическое появление приглашения U-Boot требует аппаратной проверки через BTLDR.
